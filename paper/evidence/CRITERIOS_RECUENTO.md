# Criterios fijados antes del recuento

Este análisis lee archivos publicados. No ejecuta el verifier, las tareas, scripts de los recursos ni modelos. Versiones elegidas: dataset M01 v6 y dataset M02 v8; `VERSION_SELECTION.json` se escribió antes de leer los CSV para el recuento. La metadata de `view` de M02 describía v10 y se utiliza solo para identificar la cuenta y consultar el historial, no como documentación de v8.

M01: `gradability_labels.csv`, clave `instance_id`. Se cuenta una tarea en Python 3.12 o 3.13 si su `status_py312` o `status_py313`, respectivamente, es exactamente `gradable`. Según `README.md` líneas 19–31 y `paper.md` §3.1, esto significa que el verifier oficial resuelve la referencia y no resuelve el patch vacío. No significa solo que la aplicación arranca ni que un rc es cero. `gold_fails` y `none_passes` no son válidas bajo esa regla. Se derivará la intersección de conjuntos de IDs; `gradable_both` es una comprobación secundaria de consistencia, no el filtro principal. Los CSV `evidence/gradability_py312.csv` y `gradability_py313.csv` permiten comprobar las etiquetas contra `resolved_gold`/`resolved_none`. No contienen el mismo guard explícito de dos flags de error que M02.

M02: `task_soundness.csv`, clave `task_id`. Se cuenta `sound == "1"`, comprobándolo separadamente contra `empty_resolved == "0"`, `gold_resolved == "1"`, `empty_control_error == "0"` y `gold_control_error == "0"`. Esta regla está en el README de v8, apartado Protocol and environment, y en `data_dictionary.json` → `task_soundness.csv`. El dato es posterior a overlays de dependencias en nueve tareas; no es una ejecución inicial idéntica a M01. Códigos vacíos o sentinels no se convierten en cero. Los resultados de agentes no intervienen en este recuento.

Solo se quitará whitespace exterior para detectar y documentar IDs; se conservará el valor original. No se cambiarán mayúsculas, nombres o sufijos ni se harán joins aproximados. Un ID duplicado/conflictivo o una etiqueta fuera del dominio documentado se conserva como dato ambiguo: no se elige una fila favorable. Se informarán filas, IDs únicos, duplicados, celdas vacías por columna, campos necesarios desconocidos, exclusiones y denominadores. Campos de causa o detalle vacíos pueden ser no aplicables; no son automáticamente una exclusión ni una causa desconocida de una tarea válida.

Se producirán tablas de membresía por ID y listas de ambas, exclusivas, ninguna y sin datos para M01 3.12/3.13. También se cruzará cada cohorte M01 con M02 y se conservará la intersección de las tres, distinguiendo corpus compartido y sets válidos. Un predicado desconocido nunca se imputa como falso ni como verdadero.

Las causas de fallas gold en M01/Python 3.13 se cuentan por `gold_fail_cause_py313`, con IDs y `detail_py313`. Se contrastarán con los features publicados, pero no se inferirán causas nuevas. `gold_patch_fails_tests`, errores de fixtures o colección son categorías observadas, no explicaciones causales aisladas. Los dos entornos cambian intérprete, paquetes y wheels; una diferencia entre sus controles no identifica por sí sola un efecto de Python.

Las cifras dadas por el usuario se comparan con el resultado al final. No se ajustará ninguna selección para alcanzarlas. El comando de reproducción será local y solo documental: `python recount_published_csv.py --output recount-replay`.
